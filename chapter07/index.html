    Chapter 07. 누가, 언제, 어떻게 쓸까 — 서비스 시나리오 설계¶

    Part 3. 설계 — 아이디어를 서비스로 만들기 | ⏱️ 50분

    🎯 이 장에서 배우는 것¶

    • 페르소나(가상 사용자)를 설정하고 사용자 여정 맵을 작성할 수 있다
    • 서비스의 핵심 기능을 정의하고 MoSCoW 기법으로 우선순위를 정할 수 있다
    • 한 문장 서비스 소개(엘리베이터 피치)를 작성할 수 있다

    📚 핵심 개념¶

    개념 1: 페르소나와 사용자 여정 맵¶

    1. 비유로 시작

    🎭 영화 감독이 시나리오를 쓸 때 가장 먼저 하는 일은 주인공을 만드는 것입니다. "이 사람은 몇 살이고, 무엇을 좋아하고, 어떤 고민이 있지?" — 이 질문에 답하면 자연스럽게 이야기가 흘러가죠. 서비스 설계에서 페르소나가 바로 이 주인공이고, 사용자 여정 맵이 그 주인공의 이야기 흐름입니다.

    2. 정확한 정의

    • 페르소나(Persona): 우리 서비스를 가장 대표적으로 사용할 가상의 사용자 프로필. 이름, 나이, 직업, 고민, 목표 등을 구체적으로 적는다.
    • 사용자 여정 맵(User Journey Map): 페르소나가 서비스를 발견 → 사용 → 문제 해결하기까지의 과정을 시간순으로 그린 지도.

    3. 예시로 확인

    "급식 메뉴 추천 앱"을 만든다고 가정해 봅시다.

    페르소나 카드 예시 - 이름: 김하은 (중학교 2학년) - 특징: 편식이 심함, 스마트폰 능숙 - 고민: "오늘 급식 맛있을까? 내가 싫어하는 반찬이면 어쩌지…" - 목표: 미리 메뉴를 확인하고, 자기 취향에 맞는 대안을 찾고 싶다

    journey title 김하은의 급식 앱 사용 여정 section 발견 친구가 앱을 추천해 줌: 3: 하은 앱 스토어에서 다운로드: 4: 하은 section 사용 오늘의 급식 메뉴 확인: 4: 하은 싫어하는 반찬 표시: 5: 하은 대체 메뉴 추천 받음: 5: 하은 section 해결 도시락 준비 여부 결정: 5: 하은 친구에게 앱 공유: 4: 하은

    💡 알아보기: 숫자(1~5)는 그 단계에서 사용자의 만족도를 나타냅니다. 낮은 숫자가 나오는 단계가 바로 우리가 개선해야 할 포인트예요!

    개념 2: MoSCoW 기법과 엘리베이터 피치¶

    1. 비유로 시작

    🎒 소풍 가방에 모든 걸 넣을 수는 없잖아요? 반드시 넣을 것(물, 도시락), 넣으면 좋은 것(간식), 여유 있으면 넣을 것(보드게임), 이번엔 안 넣을 것(텐트)을 나누듯, 서비스 기능도 우선순위를 매겨야 합니다. 이게 MoSCoW 기법입니다.

    2. 정확한 정의

    • Must have: 없으면 서비스가 작동하지 않는 핵심 기능
    • Should have: 있으면 훨씬 좋은 중요 기능
    • Could have: 시간이 남으면 추가할 기능
    • Won't have (this time): 이번에는 만들지 않을 기능
    graph LR A["🔴 Must<br/>반드시 필요"] --> B["🟠 Should<br/>있으면 좋음"] B --> C["🟡 Could<br/>여유 있으면"] C --> D["⚪ Won't<br/>이번엔 제외"]
    • 엘리베이터 피치(Elevator Pitch): 엘리베이터를 타고 내릴 때까지, 약 30초 안에 서비스를 설명하는 한 문장 소개.

    3. 예시로 확인

    급식 추천 앱의 MoSCoW 분류 - 🔴 Must: 오늘의 급식 메뉴 표시, 싫어하는 음식 필터링 - 🟠 Should: AI 대체 메뉴 추천 - 🟡 Could: 친구와 취향 비교 - ⚪ Won't: 영양사와 실시간 채팅

    엘리베이터 피치 공식 "[대상 사용자]가 [겪는 문제]를 해결하기 위해, [서비스 이름]은 [핵심 기능]을 제공합니다."

    예시: "편식이 심한 중학생이 급식 고민을 줄이기 위해, 오늘뭐먹지는 취향 기반 급식 필터와 대체 메뉴 추천을 제공합니다."

    🔨 따라하기 — 우리 팀 서비스 시나리오 설계¶

    🎯 실습 목표: 여러분의 서비스 아이디어에 대해 페르소나 → 여정 맵 → 기능 우선순위 → 엘리베이터 피치를 완성합니다.

    Step 1: 페르소나 카드 만들기¶

    ChatGPT에 아래 프롬프트를 입력해 보세요.

    코드 (프롬프트): 

    우리 서비스는 [서비스 설명]이야.
이 서비스를 가장 많이 쓸 것 같은 대표 사용자를 1명 만들어줘.
이름, 나이, 직업(학년), 특징, 고민, 목표를 포함해줘.

    실행 결과 (예시): 

    이름: 박준호 (고등학교 1학년)
특징: 수학을 어려워함, 유튜브로 공부하는 걸 좋아함
고민: "인강은 너무 길고, 모르는 문제만 딱 물어볼 데가 없어"
목표: 모르는 수학 문제를 사진 찍으면 바로 풀이를 보고 싶다

    💡 ChatGPT의 결과를 그대로 쓰지 마세요! 여러분이 직접 수정하고 보완하는 과정이 핵심입니다.

    Step 2: 사용자 여정 맵 그리기¶

    노트나 화이트보드에 5단계로 나눠 그려 봅니다.

    graph LR A["1️⃣ 발견<br/>어떻게 알게 되지?"] --> B["2️⃣ 첫 사용<br/>처음 열면 뭘 보지?"] B --> C["3️⃣ 핵심 행동<br/>무엇을 하지?"] C --> D["4️⃣ 결과 확인<br/>문제가 해결됐나?"] D --> E["5️⃣ 재방문<br/>다시 쓸 이유가 있나?"]

    각 단계마다 페르소나의 감정(😊😐😢)과 생각을 적어 보세요.

    Step 3: 핵심 기능 브레인스토밍 & MoSCoW 분류¶

    1. 포스트잇(또는 메모장)에 떠오르는 기능을 제한 없이 적는다 (3분)
    2. 비슷한 기능끼리 묶는다
    3. 아래 질문으로 분류한다

    🤔 생각해보기 - "이 기능이 없으면 서비스가 아예 안 되나?" → Must - "없어도 되지만 있으면 만족도가 크게 올라가나?" → Should - "있으면 재미있지만, 핵심은 아닌가?" → Could - "지금 우리 실력/시간으로 불가능한가?" → Won't

    Step 4: 엘리베이터 피치 작성¶

    아래 빈칸을 채워 한 문장을 완성하세요.

    [         ]가 [              ] 문제를 해결하기 위해,
[서비스 이름]은 [                    ]을/를 제공합니다.

    ChatGPT 활용 프롬프트: 

    아래 정보로 엘리베이터 피치를 3가지 버전으로 만들어줘.
- 페르소나: [붙여넣기]
- Must 기능: [붙여넣기]
- 서비스 이름: [입력]

    Step 5: 팀원 피드백으로 다듬기¶

    완성된 피치를 소리 내어 읽어 봅니다. 30초 안에 끝나지 않으면 줄이세요!

    ✏️ 정리하기: 좋은 엘리베이터 피치는 세 가지를 담습니다 — 누구를 위한 건지, 어떤 문제를 해결하는지, 어떻게 해결하는지.

    📝 전체 코드 — ChatGPT 프롬프트 모음¶

    # ============================================
# 서비스 시나리오 설계 — ChatGPT 프롬프트 모음
# 복사해서 ChatGPT에 붙여넣기 하세요!
# ============================================

# 1단계: 페르소나 생성
prompt_persona = """
우리 서비스: [여기에 서비스 설명 입력]
이 서비스의 대표 사용자 1명을 만들어줘.
포함할 항목: 이름, 나이, 직업(학년), 특징 2가지, 고민, 목표
"""

# 2단계: 사용자 여정 맵 초안
prompt_journey = """
위 페르소나가 우리 서비스를 쓰는 과정을
'발견 → 첫 사용 → 핵심 행동 → 결과 확인 → 재방문'
5단계로 나눠서, 각 단계별 행동과 감정을 알려줘.
"""

# 3단계: 엘리베이터 피치
prompt_pitch = """
아래 정보로 엘리베이터 피치를 3가지 버전으로 만들어줘.
30초 안에 말할 수 있는 길이로.
- 페르소나: [붙여넣기]
- 핵심 기능(Must): [붙여넣기]
- 서비스 이름: [입력]
"""

# 사용법: 위 프롬프트의 [  ] 부분을 채워서 ChatGPT에 입력하세요!
print("프롬프트가 준비되었습니다. ChatGPT에 붙여넣기 하세요!")

    실행 결과: 

    프롬프트가 준비되었습니다. ChatGPT에 붙여넣기 하세요!

    ⚠️ 주의할 점¶

    1. 페르소나 ≠ 나 자신 자기 자신을 페르소나로 설정하면 시야가 좁아집니다. "나와 다른 사람도 이 서비스를 쓸까?"를 반드시 고민하세요.

    2. Must에 기능을 너무 많이 넣지 마세요 Must가 5개 이상이면 사실상 우선순위를 정하지 않은 것과 같습니다. 최대 3개로 제한하세요.

    ✅ 점검하기¶

    1. (기본) 페르소나 카드에 반드시 포함해야 할 요소 4가지를 말해 보세요.

    정답 확인 이름(또는 가명), 나이/직업(학년), 고민(불편한 점), 목표(원하는 것). 여기에 특징이나 행동 습관을 추가하면 더 좋습니다.

    2. (응용) MoSCoW에서 'S'와 'C'의 차이를 급식 앱 예시로 설명해 보세요.

    정답 확인 **Should**(AI 대체 메뉴 추천)는 없으면 사용자 만족도가 눈에 띄게 떨어지는 중요 기능이고, **Could**(친구와 취향 비교)는 없어도 서비스 핵심에는 영향이 적은 부가 기능입니다.

    3. (심화·도전 문제) 같은 "급식 추천 앱"을 교사가 쓴다면, Must 기능이 어떻게 달라질까요? 페르소나를 새로 만들어 비교해 보세요.

    정답 확인 교사 페르소나는 "알레르기 학생 관리", "영양 균형 통계 확인" 같은 기능이 Must가 될 수 있습니다. 학생에게는 Must였던 "싫어하는 반찬 필터링"이 교사에게는 Could로 내려갈 수 있죠. **같은 서비스라도 사용자가 바뀌면 우선순위가 완전히 달라집니다.**

    📌 이 장의 핵심 요약 - 페르소나: 가상의 대표 사용자를 구체적으로 만들면 설계 방향이 명확해진다 - 사용자 여정 맵: 발견 → 사용 → 해결까지 흐름을 그려 불편한 지점을 찾는다 - MoSCoW: 기능을 Must/Should/Could/Won't로 나눠 핵심에 집중한다 - 엘리베이터 피치: 30초 안에 서비스를 설명하는 한 문장이 팀의 나침반이 된다
