    Chapter 3. 우리 팀의 문제를 정의하라¶

    🕐 예상 소요 시간: 50분

    🎯 이 장에서 배우는 것¶

    • 좋은 문제 정의의 3가지 조건(구체성, 측정 가능성, 데이터 연결성)을 설명할 수 있다
    • HMW(How Might We) 기법을 사용하여 불만을 기회 질문으로 전환할 수 있다
    • 팀 합의를 거쳐 최종 문제 정의문 1개를 확정할 수 있다

    📚 핵심 개념¶

    개념 1: 좋은 문제 정의의 3가지 조건¶

    1. 비유로 시작

    "문제 정의는 마치 내비게이션에 목적지를 입력하는 것과 같아요." '어딘가 좋은 곳'이라고 입력하면 내비게이션이 작동하지 않죠? '서울시 종로구 세종대로 1'처럼 정확하게 입력해야 경로가 나옵니다. 데이터 프로젝트도 마찬가지예요.

    2. 정확한 정의

    좋은 문제 정의란, 데이터로 답을 찾을 수 있도록 구체적이고 측정 가능하며 데이터와 연결된 질문을 만드는 것입니다.

    세 가지 조건을 기억하세요.

    • 🔍 구체성: 누가, 언제, 어디서, 무엇이 문제인지 특정할 수 있는가?
    • 📏 측정 가능성: 숫자나 비율로 표현할 수 있는가? 성공/실패를 판단할 기준이 있는가?
    • 💾 데이터 연결성: 이 문제를 풀기 위해 수집하거나 찾을 수 있는 데이터가 존재하는가?

    3. 예시로 확인

    graph LR A["😤 급식이 맛없다"] -->|변환| B["📊 우리 학교 학생의<br/>메뉴별 선호도 데이터를 분석해<br/>잔반율을 15% 줄일 수 있을까?"] style A fill:#ffcccc,stroke:#cc0000 style B fill:#ccffcc,stroke:#009900

    💡 알아보기: 왼쪽은 감정적 불만이고, 오른쪽은 데이터로 검증 가능한 문제 정의입니다. 차이가 느껴지나요?

    나쁜 문제 정의와 좋은 문제 정의를 더 비교해 봅시다.

    • ❌ "교실이 시끄럽다" → 😐 막연한 불만

    • ✅ "쉬는 시간 직후 5분간 교실 소음 데시벨이 수업 집중에 영향을 주는가?" → 🎯 구체적 + 측정 가능 + 데이터 연결

    • ❌ "운동을 안 해서 건강이 안 좋다" → 😐 범위가 너무 넓음

    • ✅ "우리 반 학생의 주간 운동 시간과 체력장 성적 사이에 상관관계가 있을까?" → 🎯 대상·범위·데이터가 명확

    개념 2: HMW(How Might We) 기법¶

    1. 비유로 시작

    "HMW는 마치 불만을 기회의 씨앗으로 바꾸는 마법 문장과 같아요." 친구가 '비가 와서 짜증나'라고 말하면, 당신이 '우리 어떻게 하면 비 오는 날도 재미있게 보낼 수 있을까?'로 바꿔주는 거예요.

    2. 정확한 정의

    HMW(How Might We) 기법은 디자인 씽킹에서 나온 방법으로, 문제를 "우리가 어떻게 하면 ~할 수 있을까?" 형태로 바꾸는 기법입니다.

    HMW 문장의 구조는 다음과 같습니다.

    "우리가 어떻게 하면" + [대상]의 + [구체적 상황]에서 + [원하는 변화]를 + "이끌어낼 수 있을까?"

    3. 예시로 확인

    graph TD P["🔴 관찰된 문제<br/>'등교 시간에 학교 앞 도로가 너무 막힌다'"] P --> H1["🟡 HMW 학생 관점<br/>우리가 어떻게 하면<br/>학생들의 등교 시간 분산으로<br/>혼잡도를 줄일 수 있을까?"] P --> H2["🟢 HMW 교사 관점<br/>우리가 어떻게 하면<br/>시차 등교 데이터를 활용해<br/>최적 등교 시간표를 만들 수 있을까?"] P --> H3["🔵 HMW 학부모 관점<br/>우리가 어떻게 하면<br/>차량 이동 경로 데이터로<br/>안전한 등교 동선을 설계할 수 있을까?"] style P fill:#ffe0e0,stroke:#cc0000 style H1 fill:#fff8dc,stroke:#daa520 style H2 fill:#e0ffe0,stroke:#228b22 style H3 fill:#e0e8ff,stroke:#4169e1

    💡 생각해보기: 같은 문제라도 관점이 달라지면 수집해야 할 데이터가 완전히 달라집니다. 학생 관점은 등교 시각 데이터, 교사 관점은 시간대별 교통량 데이터, 학부모 관점은 차량 경로 데이터가 필요하겠죠?

    🔨 따라하기: Claude에게 문제 정의문 피드백 받기¶

    2차시에서 발견한 문제 후보를 가지고, AI의 도움을 받아 다듬어 봅시다.

    Step 1: 불만을 HMW 문장으로 전환하기¶

    # 불만 → HMW 문장 전환 연습
complaints = [
    "급식이 맛없다",
    "체육 시간이 너무 짧다",
    "도서관에 읽고 싶은 책이 없다"
]

hmw_template = "우리가 어떻게 하면 {target}의 {situation}에서 {change}를 이끌어낼 수 있을까?"

# 첫 번째 불만을 HMW로 전환한 예시
example = hmw_template.format(
    target="우리 학교 학생",
    situation="급식 메뉴 선정 과정",
    change="학생 선호도를 반영한 잔반율 감소"
)

print("❌ 불만:", complaints[0])
print("✅ HMW:", example)

    실행 결과: 

    ❌ 불만: 급식이 맛없다
✅ HMW: 우리가 어떻게 하면 우리 학교 학생의 급식 메뉴 선정 과정에서 학생 선호도를 반영한 잔반율 감소를 이끌어낼 수 있을까?

    Step 2: 3가지 조건 체크리스트로 평가하기¶

    def check_problem_definition(problem_statement):
    """문제 정의문을 3가지 조건으로 평가합니다."""
    print(f"📋 평가 대상: {problem_statement}\n")

    checks = {
        "🔍 구체성": "누가/언제/어디서/무엇이 특정되어 있는가?",
        "📏 측정 가능성": "숫자나 비율로 성공을 판단할 수 있는가?",
        "💾 데이터 연결성": "수집 가능한 데이터가 존재하는가?"
    }

    score = 0
    for criterion, question in checks.items():
        answer = input(f"  {criterion} - {question} (y/n): ")
        if answer.lower() == 'y':
            score += 1
            print(f"    ✅ 통과!")
        else:
            print(f"    ⚠️ 보완 필요!")

    print(f"\n총점: {score}/3", end=" ")
    if score == 3:
        print("→ 🎉 훌륭한 문제 정의입니다!")
    elif score == 2:
        print("→ 👍 거의 다 왔어요. 한 가지만 보완하세요.")
    else:
        print("→ 🔄 문제를 더 구체적으로 다듬어 봅시다.")

# 실행 예시
check_problem_definition(
    "학생 선호 메뉴 데이터를 분석해 잔반율을 15% 줄일 수 있을까?"
)

    실행 결과 (모두 y 입력 시): 

    📋 평가 대상: 학생 선호 메뉴 데이터를 분석해 잔반율을 15% 줄일 수 있을까?

  🔍 구체성 - 누가/언제/어디서/무엇이 특정되어 있는가? (y/n): y
    ✅ 통과!
  📏 측정 가능성 - 숫자나 비율로 성공을 판단할 수 있는가? (y/n): y
    ✅ 통과!
  💾 데이터 연결성 - 수집 가능한 데이터가 존재하는가? (y/n): y
    ✅ 통과!

총점: 3/3 → 🎉 훌륭한 문제 정의입니다!

    Step 3: Claude에게 피드백 받는 프롬프트 작성하기¶

    # Claude에게 보낼 프롬프트 생성기
def create_feedback_prompt(hmw_statement, context):
    """문제 정의문에 대한 AI 피드백 요청 프롬프트를 생성합니다."""

    prompt = f"""당신은 데이터 프로젝트 멘토입니다.
아래는 중고등학생 팀이 작성한 문제 정의문입니다.

[문제 정의문]
{hmw_statement}

[배경]
{context}

다음 3가지 기준으로 피드백해주세요:
1. 구체성: 대상과 범위가 명확한가?
2. 측정 가능성: 성공 기준이 숫자로 표현 가능한가?
3. 데이터 연결성: 어떤 데이터를 수집해야 하는가?

각 기준별로 점수(1~5)와 개선 제안을 주세요."""

    return prompt

# 사용 예시
my_prompt = create_feedback_prompt(
    hmw_statement="우리가 어떻게 하면 학생 선호도 데이터로 잔반율을 줄일 수 있을까?",
    context="우리 학교 급식 잔반이 많아서 음식물 쓰레기가 문제입니다."
)

print("=== Claude에게 보낼 프롬프트 ===")
print(my_prompt)

    Step 4: 팀 투표로 최종 문제 선정하기¶

    def team_vote(problems):
    """팀원들의 투표로 최종 문제를 선정합니다."""
    print("🗳️ 팀 문제 정의 투표\n")

    for i, prob in enumerate(problems, 1):
        print(f"  {i}번: {prob}")

    print()
    votes = {}
    for prob in problems:
        votes[prob] = 0

    num_members = int(input("팀원 수를 입력하세요: "))

    for member in range(1, num_members + 1):
        choice = int(input(f"  팀원{member}의 선택 (번호): "))
        votes[problems[choice - 1]] += 1

    winner = max(votes, key=votes.get)
    print(f"\n🏆 최종 선정: {winner}")
    print(f"   (득표수: {votes[winner]}/{num_members})")
    return winner

    📝 전체 코드¶

    # === Chapter 3: 문제 정의 도구 모음 ===

# 1. HMW 문장 생성기
def make_hmw(target, situation, change):
    return f"우리가 어떻게 하면 {target}의 {situation}에서 {change}를 이끌어낼 수 있을까?"

# 2. 문제 정의 체크리스트
def check_problem(statement):
    print(f"📋 평가: {statement}\n")
    criteria = ["🔍 구체성", "📏 측정 가능성", "💾 데이터 연결성"]
    score = 0
    for c in criteria:
        ans = input(f"  {c} 충족? (y/n): ")
        if ans.lower() == 'y':
            score += 1
    print(f"\n결과: {score}/3 {'✅ 통과' if score == 3 else '🔄 보완 필요'}")

# 3. AI 피드백 프롬프트 생성
def make_prompt(hmw, context):
    return f"""데이터 프로젝트 멘토로서 아래 문제 정의문을 평가해주세요.
[문제 정의문] {hmw}
[배경] {context}
구체성/측정 가능성/데이터 연결성 기준으로 피드백 부탁합니다."""

# === 사용 예시 ===
hmw = make_hmw("우리 학교 학생", "급식 메뉴 선정", "잔반율 15% 감소")
print(hmw)
check_problem(hmw)
print(make_prompt(hmw, "급식 잔반이 많아 음식물 쓰레기 문제 발생"))

    • ❌ 너무 작음: "내 친구 민수가 급식을 안 먹는 이유" → 일반화할 수 없음
    • ✅ 적당함: "우리 학교 1학년의 메뉴별 잔반율 차이를 분석할 수 있을까?"

    2. '느낌'이 아니라 '데이터'로 답할 수 있는 질문인지 확인하세요

    "급식이 행복하게 느껴지려면?"은 데이터 프로젝트 문제가 아닙니다. "잔반율이 낮은 메뉴의 공통 특징은?"은 데이터로 답할 수 있는 좋은 문제입니다.

    ✅ 점검하기¶

    📌 정리하기: 이 장에서 배운 핵심을 확인해 봅시다.

    기본 문제 1. 다음 중 좋은 문제 정의는 어느 것인가요?

    • (가) 우리 학교 시설이 불편하다
    • (나) 우리 학교 화장실 이용 시간대별 혼잡도를 분석하여 쉬는 시간 조정으로 대기 시간을 줄일 수 있을까?
    정답 확인 **(나)**가 좋은 문제 정의입니다. - 구체성 ✅: 화장실, 시간대별, 쉬는 시간이라는 구체적 범위 - 측정 가능성 ✅: 혼잡도, 대기 시간이라는 측정 지표 - 데이터 연결성 ✅: 시간대별 이용 인원 데이터 수집 가능 (가)는 막연한 불만일 뿐, 데이터 프로젝트의 출발점이 될 수 없습니다.

    응용 문제 2. "학교 앞 교통이 위험하다"를 HMW 문장으로 전환해 보세요.

    정답 확인 예시 답안: **"우리가 어떻게 하면 등하교 시간대 학교 앞 차량 통행량 데이터를 활용해 안전한 통학로를 제안할 수 있을까?"** 핵심은 '위험하다'라는 감정을 '차량 통행량'이라는 측정 가능한 데이터로, '안전한 통학로 제안'이라는 구체적 목표로 바꾸는 것입니다.

    심화 문제 3. 🏆 도전! "학교 도서관 이용이 저조하다"는 문제를 학생·교사·학부모 3가지 관점에서 각각 HMW 문장으로 작성해 보세요. 각 관점에서 필요한 데이터가 어떻게 달라지는지도 적어 보세요.

    정답 확인 - **학생 관점**: "우리가 어떻게 하면 학생들의 관심 분야별 희망 도서 데이터를 수집해 대출률을 높일 수 있을까?" → 필요 데이터: 학생 관심 분야 설문, 현재 대출 기록 - **교사 관점**: "우리가 어떻게 하면 교과 연계 도서 추천 데이터를 분석해 수업과 독서를 연결할 수 있을까?" → 필요 데이터: 교과별 추천 도서 목록, 교과 진도표 - **학부모 관점**: "우리가 어떻게 하면 자녀 독서 시간 데이터를 활용해 가정 독서 환경 개선 방안을 찾을 수 있을까?" → 필요 데이터: 가정 내 독서 시간 조사, 독서 환경 설문 👉 같은 문제도 관점이 달라지면 수집할 데이터와 해결 방향이 완전히 달라집니다!
